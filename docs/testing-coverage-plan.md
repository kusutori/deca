## 2) 分阶段执行策略

### 第一轮（目标：每个重点包先到 60%+）

- 先做 P0 中低于 60% 的包：`internal/install`、`internal/ui`、`internal/download`、`internal/github`。
- 并行补齐 P1：`cmd` 的高频命令路径与关键 flag 分支。
- 优先“无外部依赖或可注入依赖”模块：
  - `internal/github`：mock `http.RoundTripper` 覆盖 release/asset 分支。
  - `internal/download`：mock downloader/临时目录夹具覆盖 checksum、缓存命中/失配。
  - `internal/install`：分离系统调用层，注入 runner 覆盖错误分支。
  - `internal/ui`：将输出 writer 注入，覆盖 color/error/selector 分支。

### 第二轮（目标：核心包到 80%+）

- 聚焦 P0 六个核心包：`config/cache/install/download/github/ui`。
- 针对未覆盖的复杂分支做表驱动测试：
  - 多平台路径展开与权限异常；
  - 资产匹配与镜像 URL 转换边界；
  - 安装回滚、sudo 流程的失败恢复；
  - 条件表达式解析器异常路径。

### 第三轮（目标：整体到 80%+）

- 通过 P1/P2 补缺口，把总覆盖率从当前 **38.4%** 提升到 **80%+**。
- 引入端到端 smoke test（最小化真实外部依赖）补齐 cmd 间接覆盖。
- 对长期低收益的薄封装代码采取“契约测试 + 集成回归”策略，避免过度mock。
